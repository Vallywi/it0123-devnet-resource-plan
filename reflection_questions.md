# 11. Reflection Questions

## 1. Which scenario was easiest to classify, and which requirement determined your choice?

UC-04 was the easiest to classify because it clearly needed an existing automation example or reusable code repository. That requirement directly matched Cisco Code Exchange, since Code Exchange is used for finding sample solutions and implementations.

## 2. Describe one AI claim that needed correction, qualification, or rejection.

One AI claim that needed qualification was that an Always-On Sandbox is best for API tasks. I verified that it is useful for quick shared access, but it is not suitable for every case, especially when the task requires private isolation, administrative control, VPN access, or configuration changes.

## 3. Why is an Always-On Sandbox not automatically the best option for every API task?

An Always-On Sandbox is not automatically the best option because it is shared and usually limited. It works well for quick API exploration, but API tasks that need private access, administrative privileges, or configuration testing are better suited for a Reservation Sandbox.

## 4. How did Git improve the traceability of your resource-selection process?

Git improved traceability by recording the activity progress through commits. It showed when the activity scaffold was created and when the completed validation plan was added, making the resource-selection process easier to review and verify.
